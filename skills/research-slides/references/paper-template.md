# 資料・テーマとテンプレートから作る

## 1. 役割ごとに枠を選ぶ

`node src/cli.mjs read template.pptx out/run/template-index.json` でページ寸法、レイアウト、枠の種類・idx・座標・継承書式を調べる。レイアウトの番号や枠IDは毎回この索引から得る。レイアウト名と種類、枠の位置と面積、参考ページでの使われ方を合わせて確認する。先頭ページや本文型の枠があるだけで、本文向きと判断しない。

まず表紙と、本編の共通本文レイアウトを選ぶ。図・式・比較ページでも、基準のタイトルと本文の枠を使い、空き領域に図や式を置けるか検討する。別レイアウトを使うページは役割を明示し、文字の起点・大きさ・全体の流れを他ページと照合する。普通の本文ページを例外扱いにして書式のばらつきを残さない。

適したレイアウトの文字枠には `add-slide-from-layout` を使う。元ページの独自の枠がデザインの要なら、適した元ページを `duplicate-slide` で複製し、同じ枠の段落を置き換える。後者の個別書式も参考ページの設計として扱う。どちらで進めるか決められない場合は枠の用途を描画で確認し、対応できる枠がなければ具体的な制限を伝える。操作の契約は[直接編集](editing.md)を参照する。

## 2. 内容・図・式を同時に割り当てる

[説明設計](research.md)を使い、PDFがあるときは[PDF入力](pdf-input.md)も参照する。発表時間に収まる本編と補足を決め、各ページの要点、本文、根拠、図で示す関係、使う枠を記録する。図を使うページは構成段階で配置領域を確保し、ラベルと出典または自作方針を決める。

図や根拠は、まず提供された文献・資料から探す。補足が必要で調査できる場合は、一次資料や公式資料で内容を確認し、引用する図には出典を付ける。適した図が見つからない、または対象者に合わせて単純化したい場合は、確認した内容をもとに模式図を作る。例示の数値と実測データは区別する。図の選択が発表の方向を左右し、資料だけでは決められない場合は、候補と違いを示して質問する。

- 構造・処理の流れ・比較を示す模式図には、箱・矢印・短いラベルを使う。本文は図で伝わらない要点に絞る。自作図は必要に応じて「説明用の模式図」と記し、参照資料があれば出典を添える。
- テンプレートを使うときは、自作の図をPNGに書き出して `add-image` で挿入できる。単純な図はSVGで設計し、ローカルのレンダラーでPNGに変換する。図を採用したページは埋め込みの照合に加え、ラベル、本文との重なり、余白を描画で確認する。余白だけを埋める装飾は加えない。
- タイトルと本文は選んだ枠へ入力する。箇条書きは段落で渡し、点や記号を別図形にしない。従属する説明は `{"text":"説明や条件","level":1}` で下位段落にできる。文字が逆に大きくなる、箇条書きが出ないなどの違いは実際の表示で判断し、別の本文レイアウトや浅い階層を選ぶ。
- 図は与えられた文献・資料で出典・ラベル・切り出す範囲を目で確認する。`read-pdf` のPNGを `add-image` で挿入するか、対応する画像枠を `replace-image` で差し替える。配置は索引のEMU寸法を使い、画像の代替テキストとスライド上の出典を付ける。
- 式は原文の上下付き・分数・根号・括弧を照合する。通常文字で読みづらい式は文献の式を高解像度で切り出し、投影で読める幅を確保する。式番号と出典、変数の意味は読める形で添える。画像の式を記号単位で編集できるとは扱わない。
- 結論を強調するときは、参考ページに用途の合う強調枠があれば活用する。枠がない場合は本文の結びに短く置く。アクセントはテンプレートの書式に合わせる。

計画を `node src/cli.mjs edit template.pptx out/run/edit-plan.json out/run/candidate.pptx` で実行する。新しい発表に不要な元ページは削除し、他の研究の文章・図・ノートが出力に残っていないか確認する。私有の計画、索引、図、PPTXは `out/` に置く。

## 3. 基準を検査し、見て直す

初稿を描画したら、図から関係が追えるか、投影時にラベルが読めるか、本文や前後ページの図と説明が重複していないかを確認する。問題があれば要点・図の選択・本文量を設計案で直し、編集計画に反映して再描画する。

出力を `inspect` と `read` で検査する。さらに基準枠と例外ページを `out/run/template-review.json` に記録し、実ファイルを照合する。

```text
node src/cli.mjs check-template template.pptx out/run/candidate.pptx out/run/template-review.json
```

`baseline` には、レイアウト追加なら `layoutPart`、`titleIdx`、`bodyIdx` を、元ページ複製なら元PPTXの `slideId`、`titleShapeId`、`bodyShapeId` を指定する。idxは整数、IDは文字列。いずれも今回の入力索引の上位の枠から得る。`exceptions` は基準と役割が違うページだけを `{"page":1,"reason":"表紙"}` の形で列挙する。ページ番号は出力の1始まりで、該当なしなら空配列にする。

図や式の採用を決めた時点で、`assets` に出力の `page` と挿入する画像のSHA-256（PDF抽出時は索引の `assets[].sha256`） を記録する。検査は指定ページの埋め込み画像と照合する。出典の正しさと図・式の読みやすさは原本と描画で確認する。

検査は元のマスター等の保持、レイアウトへの参照、通常ページの基準枠と座標・一部の書式を確認する。失敗したページは元の枠とレイアウトを見直して修正する。検査だけでは自動縮小や実際の折り返しは分からないため、[確認と修正](quality.md)の手順で全ページを描画して見直す。「例え｜ば」のような分断は意味が通る短い表現へ直す。行を変える場合も一つの語や意味のまとまりを切らず、箇条書きの同じ項目を見かけだけで別項目にしない。

レイアウトの選び直しやページ分割は、元テンプレートからの編集計画へ反映する。候補の文言だけを直す場合は、候補を読み直して新しい索引のIDとハッシュを使う。修正した候補で検査と描画を繰り返し、確認できた最終版を返す。環境や入力により確認できなかった点は具体的に添える。
