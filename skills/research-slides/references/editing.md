# 既存PPTXを編集する

リポジトリルートから `node src/cli.mjs read source.pptx out/read-v1/index.json` を実行し、索引の `issues`、`limitations`、入力SHA-256を確認する。未解釈要素があることと、元XMLを保持できることを区別する。

既存ページの複製や通常ランの文字変更は `node src/cli.mjs edit source.pptx plan.json out/edited-v1.pptx` を使う。計画の型は `src/pptx/edit/plan.mjs`、具体例と制限は `docs/pptx-edit.md`。推測したページ番号や図形名で操作せず、索引のページID・図形ID・親グループ・段落/ラン位置・置換前の文字を使用する。

- 段落を替える場合は `replace-paragraph-text`、未結合の表セル内段落は `replace-table-cell-paragraph` を使える。行・列・段落は0始まり。例と型は上記の仕様を参照する。
- 図形内の段落数を変える場合は `insert-paragraph` / `delete-paragraph` を使う。位置は直前の操作後の状態を基準にする。書式元と削除対象の文字を照合し、最後の段落は残す。文字範囲アニメーションがある場合は未対応。
- 既存レイアウトから作る場合は `add-slide-from-layout` に登録済みパーツ名とidx別の本文を渡す。座標やフォントをローカル指定せず共通書式を使う。写真枠等は未対応で、日時・フッター・ページ番号等の補助枠はレポートに省略を記録する。元ページの内容や個別装飾を使う場合は複製と区別する。
- ページ削除は `delete-slide`、順序変更は `reorder-slides`。順序変更には現在の全ページを1回ずつ指定する。他からの参照が残る削除やセクションをまたぐ移動は拒否する。削除は機密情報の完全消去ではなく、画像・ブック・文書キャッシュ等が残り得る。
- 白紙に文字枠がない場合は `add-text-shape` を使える。座標/寸法はEMU、書式は明示する通常テキスト枠。自動縮小をせず描画を確認する。マスターと連動する本文プレースホルダーではないため、共通書式を継承したと報告しない。具体例と検証は `docs/pptx-edit.md`。
- 文字の大きさ・書体を変える場合は `set-text-style`。指定図形または表全体へのローカル上書きであり、マスター編集ではない。`fontFace`、`fontSizePt`を明示する。箇条書きを外すときだけ`removeBullets:true`、揃え方を変えるときだけ`alignment`を指定する。
- `set-shape-position`は回転・反転のない上位図形にEMUで位置と寸法を指定する。グループ内座標、自動文字組み、表の行高調整は扱わない。変更後は描画して確認する。
- `replace-image`はPNG/JPEGのdata URLと`box`（EMUのxEmu/yEmu/widthEmu/heightEmu）を指定する。元画像を共有していても新しい資産へ参照を付け替え、縦横比を保って枠へ収める。元のトリミングは解除する。`alt`に内容の説明を付ける。上位の通常画像に限定し、効果やタイル等は拒否する。
- `add-image`は同じ`data`、`box`、`alt`でPNG/JPEGを追加する。図や式の出典はスライド本文にも示す。
- 不要なテンプレートの図形は`delete-shape`で対象IDを指定する。接続・アニメーションから参照されている場合は拒否する。関連画像・文書キャッシュの完全消去ではない。
- `set-speaker-notes`は、既存の専用ノートに本文プレースホルダーが1個ある場合に使う。`expectedText`で古い本文と照合し、`paragraphs`で置換する。ノートなし・共有ノート・複製先aliasのノート作成/編集は未対応。今回作成した別名出力を読み直し、そのページIDで既存ノートを編集することはできる。
- 段落の混在書式を黙って統一しない。全体を特定ランの書式にする意図がある場合だけ `styleFromRun` を指定する。異なる書式を保つならランごとに編集する。
- リンク・改行・フィールド・数式等を含む段落の一括置換と結合セルは未対応。通常の文字へ変換して失わない。文字サイズを勝手に下げず、変更後に描画して枠内に収まるか確認する。
- 元のリンク・箇条書き・個別書式を保持する。個別書式がある資料を、複製だけで共通書式の一括変更が可能になったと扱わない。
- 未対応操作を別の生成経路に黙って置き換えない。必要な編集操作を追加実装してから実行する。
- レポートの変更/追加パーツと共有範囲を確認する。ノート・グラフ・埋め込みブックの分離と、値の編集・照合は別の機能である。
- 最終出力を描画し、変更ページと原本の対応ページを比較する。アプリ上の編集性は構造検査とは別に確かめる。
