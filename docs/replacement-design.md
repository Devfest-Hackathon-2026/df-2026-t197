# PPTX作成・編集・テンプレート継承：機能設計案 v0.2

作成: 2026-11-06。実装前の設計案。現在の `specification.md` は新規生成の試作範囲を示す文書として残す。本書に記載した機能の多くは未実装。

## 1. 前提と目標

必須用途は新規作成、参考PPTXそのものの編集、テンプレートの継承。輪講を初回の評価例にするが、PPTX操作の中核を論文専用にしない。当面の開発・検証はCodex。大会の完成品のAIとCloud接続は別に決める。

既存skillのMD・補助コード・専用のインポート/最終化機能を実行時依存にしない。一般の公開ライブラリや外部描画ツールは、利用条件と版を記録して依存として管理する。AIの既存知識まで排除できたとは主張しない。

ユーザー指定によりAGENTS.mdは編集せず、GitHubへのpush・PR作成・マージも行わない。

## 2. 3つの操作モード

| モード | 入力 | 変更するもの | 保持するもの | 出力 |
| --- | --- | --- | --- | --- |
| create | 短い依頼、内容資料、任意の外観参考 | 新しい資料の内容・構成・配置 | 指定された内容、出典、必要な編集性 | 新規PPTX、プレビュー、検査・実行記録 |
| edit | 既存PPTX、修正依頼 | 指定要素と必要な関連部品 | 対象外の内容・書式・参照・ノート・未知の部品 | 別名PPTX、変更記録、前後比較 |
| template | PPTX/POTX、内容、元ページ/レイアウトの対応 | 内容、必要なページ数、許可された配置 | 寸法、マスター、レイアウト、テーマ、必要な装飾や枠 | 継承した新資料、保持・操作確認の記録 |

「参考にする」だけではedit/templateを自動選択しない。判断できる指示を優先し、差が成果物へ影響する場合にだけ確認する。

## 3. 責務と依存

| 層 | AIの担当 | コード/ツールの担当 |
| --- | --- | --- |
| 入力理解 | 目的、聴衆、変更意図、参考範囲 | ファイル種別、ハッシュ、内容・構造の抽出 |
| 作成計画 | 説明、構成、元ページとの対応 | 計画の型・対象・実行可能性を検証 |
| 実行 | 必要な操作を選ぶ | 生成・編集・複製・保存を限定された操作で実行 |
| 検査 | 内容・見た目・要求への適合を判断 | 構造、変更範囲、データ、配置の診断、描画 |
| 修正 | 問題に対する修正方法を選ぶ | 指定範囲で修正し、再検査・再描画 |
| 納品 | 制限と未解決事項を短く説明 | 出力と入力/版/実行履歴を結び付ける |

候補構成は、skill本体、用途別MD、PPTX索引、操作計画、生成/編集/テンプレート処理、検査、描画、実行環境、記録。Python/Nodeの分担は未確定。必要な機能を基準に選び、既存と同じ言語・ファイル構成であることを目的にしない。

## 4. 全操作共通の契約

- 原本は変更せず、新しい出力名へ保存する。保存前の検査に失敗した出力を完成品と扱わない。
- 入力ハッシュと対象を操作計画へ含める。別の版の資料へ古い計画を適用しない。
- 既存資料はZIP内の物理ファイル名順ではなく、presentationのページ一覧と参照から実際の順番を求める。
- ページ番号、内部ページ部品、図形ID、プレースホルダー情報を対応付ける。新規生成JSONのIDと既存PPTXのIDを同一視しない。
- 対象外の内部部品は、原則として展開後バイト列のハッシュを保持する。ZIPコンテナ全体のバイト一致は求めない。変更が必要な登録ファイルは許可リストと理由を記録する。
- 未知の部品は読み取れないことと保持できないことを分ける。保持できるだけなら内容の正確性を検証済みとはしない。
- 対応できない操作は、実行前に失敗として返す。代替画像化、内容の削除、資料全体の再生成を無断で行わない。
- 編集の書き出しは一時出力で検証後、新規ファイルへ確定する。途中失敗で原本や半端な完成品を残さない。

## 5. 機能ごとの契約

### R01 依頼の分類と計画

入力: 依頼文、資料、前提。出力: モード、要求内容、保持条件、変更対象、未確定事項を含む計画。AIが選び、コードが存在しないページ・要素や未対応操作を拒否する。

根拠領域: A01/O01/C01。合格: create/edit/templateで実行経路を区別し、editを黙ってcreateへ変更しない。

### R02 内容・構造の索引

入力: 既存PPTX。出力: 実ページ順、非表示状態、寸法、タイトル/本文/ノート、図形ID・種類・位置、グループ階層、画像、表、グラフ、内部/外部参照、マスター・レイアウト・テーマ、継承と直接書式の情報。

テキスト抽出は数式・画像中の文字を完全に読めるとは宣言しない。複雑な描画要素はプレビューへ対応付ける。外部参照は列挙し、自動でアクセスしない。

根拠領域: A04/A09/O09/O12/C06。合格: ファイル順と表示順が異なるfixture、複数マスター、画像・表・ノートを正しく識別する。

### R03 資料抽出と根拠の管理

入力: 論文PDFや内容資料。出力: ページ・図表・数値と出典の対応。AIによる読解と、抽出ツールの取得結果を区別する。過去資料の人物名や別研究の主張を新しい論文の内容へ混ぜない。

根拠領域: A01/O01、ユーザーの輪講用途。合格: 主要数値と図表を原本で照合でき、読めない箇所を創作しない。

### R04 新規生成

入力: 内容計画、デザイン指定、素材。出力: 編集可能な文字・図形・表・グラフ・ノート・出典を持つ新規PPTX。固定5種類のレイアウトだけで利用者の要求を削らない。既存生成JSONは一経路として再利用する。

根拠領域: A01/O01/O02/C03/C04。合格: 日本語・長いタイトル・表・グラフ・画像を含む資料で、内容と表示と編集操作を確認する。

### R05 既存テキスト・書式の編集

入力: 元PPTXのハッシュ、対象ページ/図形/段落等、置換内容。出力: 変更部品の一覧と別名PPTX。単純な置換、段落の差し替え、書式変更を別の操作として定義する。

単純な文字置換では段落と書式単位を保つ。複数の書式単位にまたがる置換で新しい文字の書式が一意に決まらない場合は、書式指定がなければ曖昧として返す。既存のリンク・箇条書き・数式等を、平文への変換で無言に失わない。

根拠領域: A01/A09/O03、ユーザー必須要件。合格: 対象外ページの部品ハッシュを維持し、混在書式・リンク・ノートを保持する。

### R06 画像・図形・表・グラフの編集

画像差し替えでは元の領域・トリミング・縦横比のどれを保持するか指定する。共有画像の実体を上書きせず、必要なら新しい資産へ参照を付け替える。

図形の位置・寸法・文字、表セルの値・書式を対象指定で変える。結合セルやグループを無視しない。グラフの値の変更では、系列・軸・表示用値・埋め込みワークブックを照合する。外部ワークブックや計算式の保持は別条件として扱う。

根拠領域: A10/O06/O14〜O16/C04。合格: 他ページへ変更が波及せず、元データと表示が一致する。未対応形式は対象操作だけを拒否する。

### R07 テンプレート継承

入力: 元PPTX/POTX、内容、元ページ/レイアウトと内容の対応。出力: 元の共通書式を使った資料と保持結果。

3つを別に判定する: (1)外観が合う、(2)マスター・レイアウト・テーマとプレースホルダーの参照を保つ、(3)後日の共通書式変更・ページ追加が機能する。

文字を枠へ入れるだけでなく、タイトル/本文の役割、複数の本文枠、継承、個別書式、不要な枠の削除を計画する。原本の装飾・ロゴ等は必要なものを保持する。元の個別書式を一律に削る処理を適用しない。

根拠領域: A02/O03/O09〜O11/C05。合格: 複数レイアウトと個別書式のある自作fixtureで、外観・参照・後日の操作をそれぞれ確認する。

### R08 ページの追加・複製・削除・順序変更

レイアウトからの新規追加と、内容付きページの複製を分ける。追加時は一覧・ID・参照・種類を整合させる。順序変更は実際のページ一覧へ反映する。

複製時はグラフ・埋め込みデータ・ノート等、独立して変更すべき部品を原則として複製する。共通のマスターや変更しない画像を共有する場合は共有範囲を記録する。依存先を理解できず独立性を保証できない複製操作は、無言に共有せず失敗とする。

削除後の整理は、参照を解析して到達可能な部品を保つ。解析失敗を全削除と解釈しない。ノート・非表示ページ・セクション・ページ番号への影響も確認する。

根拠領域: A02/A03/A09/O10/C07。合格: 複製先のノートとグラフ値を変えても元ページが変わらない。

### R09 素材変換と形式対応

PNG/JPEGに加え、SVGや透過画像、必要なベクター形式・数式の扱いを機能表に載せる。変換する場合は元素材を保ち、解像度・寸法・透明度・編集上の制限を記録する。

ネイティブ数式、複合グラフ、SmartArt、動画、旧PPT、結合/分割も対象機能表から消さず、対応手段と試験を別に定義する。実装前には対応済みと宣言しない。

根拠領域: A01/O06/O19/C04。合格: 宣言した対応形式で表示と保持条件を満たし、非対応形式を検出する。

### R10 構造・データの検査

入力: 候補PPTX、原本、操作計画。出力: 対象ページ/部品、重大度、診断コード、検査済み/未検査、修正の手がかり。

基本整合に加え、ID、参照型、内容種類、ページ/レイアウト/マスター/ノート、テーマ、グラフ、埋め込みデータ、必要なスキーマ検査を対象にする。原本にもあった問題と、新しく生じた問題を区別する。宣言された表計算やグラフデータを照合する。

根拠領域: A06〜A13/O05/O12〜O16/C06。合格: 壊れたfixtureを意図した診断で検出する。部品数だけで編集性を合格にしない。

### R11 配置・フォント・描画

入力: 最終候補PPTX、必要なら原本。出力: ページに対応した画像、一覧、描画環境・フォント・失敗記録。

日本語と数式・図中ラベル、枠外・重なり・文字切れ、読みやすい情報量、元資料との一致を確認する。文字数推定は診断の一つであり、描画の代替ではない。自動判定が意図した重なりを警告した場合は、根拠を残して判断する。

根拠領域: A04/A05/O02/O13/O17〜O19/C09。合格: 本文・図表・ノート・非表示状態と画像の対応が取れ、PowerPoint/他環境の差を記録する。

### R12 修正・最終化・記録

入力: 問題一覧と候補出力。出力: 修正後のPPTX、検査/描画、変更理由、残った問題。AIの判断とコードの実行結果を結び付ける。

入力・モデル・指示書・コード・依存版・変更部品・検査環境を記録する。ハッシュだけでAIの読み込みを証明しない。修正の上限を明示し、未解決なら失敗/制限を伝える。未確認を合格へ書き換えない。

根拠領域: A01/O05/O20/C08/C10。合格: 依頼から出力まで追跡でき、既存skillや補助コードを実行に使った場合に検出・記録できる。

## 6. 操作計画とエラーの設計案

操作計画に含めるもの: 入力ハッシュ、モード、対象ページ/図形等、操作種別、変更内容、保持条件、関連部品、期待結果。JSON全体への自由なプログラム実行や、任意パスの書き換えを許可する形式にはしない。

初期の操作候補は、文字置換、段落差し替え、書式変更、画像差し替え、図形の位置変更、表セル変更、グラフ系列変更、レイアウトから追加、複製、削除、並び替え。

| 診断コード案 | 条件 | 動作 |
| --- | --- | --- |
| STALE_INPUT | 入力の版が計画と違う | 書き出さず再索引を要求 |
| TARGET_NOT_FOUND / AMBIGUOUS_TARGET | 対象なし/複数候補 | 対象外を推測して編集しない |
| UNSUPPORTED_EDIT | 対象機能を保って操作できない | 未対応範囲と代替案を報告 |
| PRESERVATION_FAILED | 対象外の部品を変更・欠落 | 出力確定を止める |
| RELATIONSHIP_INVALID | 参照不整合 | 部品と参照を診断 |
| DATA_MISMATCH | 表示用値・系列・ワークブックの不一致 | 原因を報告し修正後に再検査 |
| RENDER_FAILED / FONT_MISSING | 描画失敗/必要フォントなし | 未確認とし、置換を勝手に決めない |
| CONTENT_TOO_DENSE | 過密の疑い | AIが分割等を判断、内容を無断削除しない |
| OUTPUT_EXISTS | 出力先が存在 | 原本・旧版を上書きしない |

これらは将来の契約案であり、現在のCLIが既に返すコードではない。

## 7. 拡張する文書・コードの候補

skill本体は入口と振り分けに集中し、作成/編集/テンプレート/検査の詳細を用途別MDに分ける。論文用の説明設計は用途別資料として残す。

コードの候補モジュール: `package-reader`、`content-index`、`edit-plan`、`package-editor`、`template-builder`、`slide-operations`、`asset-conversion`、`structure-checks`、`data-checks`、`render-backends`、`review-report`。名前は提案であり、既存のファイル名をそのまま再現する必要はない。

現行の生成器・新規生成スキーマ・画像寸法・保存保護・描画経路・基本検査は再利用する。汎用編集器へ現行の狭い構成JSONを強制しない。自作生成物専用の継承補正を既存資料へ広げない。

## 8. 実装順序と未決事項

依存順は、索引と原本保持 → 限定した直接編集 → レイアウト/ページ操作と参照管理 → データ検査・描画・保持比較 → AIの反復手順 → Cloud接続。

日曜の最小デモでも3モードの一連の動作を対象にする。必須機能自体を消さず、各操作の対応範囲と未実装を報告する。

方式選定前に確認するもの: 編集器の実装言語、XML保持方針と利用ライブラリ、スキーマ検証の入手元と利用条件、Linux描画と日本語フォント、実資料と公開fixture、入力サイズ・時間制限、AIモデルと実験条件。

本書だけで完全な同等性を宣言しない。詳細コードの未読部分は `source-capability-map.md`、機能ごとの試験は `replacement-acceptance.md` に追跡する。
